    RAG

    RAG 检索增强生成（Retrieval Augmented Generation），通过自有垂域数据库检索相关信息，然后合并成为提示模板，给大模型润色生成回答；

    通用的基础大模型无法完成实际业务需求的原因如下： + 知识的局限性：现有主流大模型的训练集是基于网络公开的数据集，对于一些实时性，非公开的或私域的数据是没有的； + 幻觉问题：所有的深度学习模型的底层原理都是基于数学概率，模型输出实质上是一系列数值运算，包括大模型； + 数据安全性；

    RAG（中文为检索增强生成） = 检索技术 + LLM 提示

    RAG（Retrieval-Augmented Generation）检索增强生成：先从资料库里检索相关内容 再基于这些内容来生成答案；RAG融合是一种用于（可能）提升RAG应用检索阶段的技术；

    为什么不每次向模型发送问题时加入产品手册？ + 模型无法读取全部内容 超过上下文窗口 + 模型推理成本高 + 模型推理慢

    RAG就是将冗长的产品手册分成小的片段 当用户向模型提问时 会选择和用户提问相关的片段和提问一起发送给模型；

    RAG架构可以理解为检索 + 生成，前者是利用向量数据库的高效存储和检索能力，召回目标知识；后者则是利用大模型和Prompt工程，将召回的知识合理利用，生成目标答案。

    RAG的基本流程就是准备（提问前）：分片→索引；和回答（提问后）：召回→重排→生成；也可以看作两个阶段： + 数据准备阶段：数据提取——>文本分割——>向量化（embedding）——>数据入库； + 应用阶段：用户提问——>数据检索（召回）——>注入Prompt——>LLM生成答案；

    分片的方式：按字数分，按段落分，按章节分，按页码分等等； 索引就是通过Embedding将片段文本转换为向量，再将片段文本和片段向量存入向量数据库中； Embedding：文本转换为向量的过程；含义相近的文本他们对应的向量也是相近的；专门的Embedding模型来做； https://huggingface.co/spaces/mteb/ 向量数据库：用于存储和查询向量的数据库；至少有原始文本和向量两列内容；

    用户输入问题后 通过Embedding转换为向量 然后利用向量相似度计算公式 计算向量数据库中每个向量和用户输入问题向量的相似度 最后得出相似度最大的前几个向量； 召回就是从所有片段中选出相似度最大的前几个向量；

    向量相似度计算： + 余弦相似度；两个向量之间的角度的余弦值 + 欧氏距离；两个向量终点之间的距离 + 点积；考虑方向和长度![[Pasted image 20260710205157.png]] 判断两个向量在同一个方向努力的程度；A在B上作垂线 然后垂线的长度和B的长度作乘积；

    重排就是在召回的结果中再选出几份和用户问题相似度最大的； 召回和重排阶段使用的与用户问题相似度计算逻辑不同：重排一般使用cross-encoder，成本高 耗时长 准确率高；召回是计算向量相似度，成本低 耗时短 准确率低 适合初步筛选；

    生成是大模型根据用户问题和我们选出来的参考资料来生成答案；

    数据准备阶段

    一般是一个离线的过程，主要是将私域数据向量化后构建索引并存入数据库的过程；主要包括：数据提取、文本分割、向量化、数据入库等环节；

    数据提取

    • 数据加载：包括多格式数据加载、不同数据源获取等，根据需要，将数据处理为同一个范式；
    • 数据处理：包括数据过滤、压缩、格式化等；
    • 元数据获取：提取数据中关键信息，例如文件名、Title、时间等；

    文本分割

    文本分割主要考虑两个因素： （1）embedding模型的Tokens限制情况； （2）语义完整性对整体的检索效果的影响； 常见的文本分割方式是句分割（标点符号）和固定长度分割（根据embedding模型的token长度限制，将文本分割为固定长度（如1024/512个tokens），这种切分方式会损失很多语义信息，一般通过在头尾增加一定冗余量来缓解）；

    向量化（embedding）

    向量化是一个将文本数据转化为向量矩阵的过程，该过程会直接影响到后续检索的效果；

    常见的embedding模型 描述
    ChatGPT-Embedding 由OpenAI公司提供，以接口形式调用
    ERNIE-Embedding V1 由百度公司提供，依赖于文心大模型能力，以接口形式调用
    M3E 开源Embedding模型，包含m3e-small、m3e-base、m3e-large等多个版本，支持微调和本地部署
    BGE 由北京智源人工智能研究院发布，一款开源Embedding模型，包含了支持中文和英文的多个版本，同样支持微调和本地部署
    #### 数据入库
    数据向量化后构建索引，并写入数据库的过程可以概述为数据入库过程；适用于RAG场景的数据库包括：FAISS、Chromadb、ES、milvus等；
    ### 应用阶段
    在应用阶段，可以根据用户的提问，通过高效的检索方法，召回与提问最相关的知识，并融入Prompt；大模型参考当前提问和相关知识，生成相应的答案；关键环节包括：数据检索、注入Prompt等；
    #### 数据检索
    常见的数据检索方法包括：相似性检索、全文检索等，根据检索效果，一般可以选择多种检索方式融合，提升召回率；
    + 相似性检索：计算查询向量与所有存储向量的相似性得分，常见的相似性计算方法包括：余弦相似性、欧氏距离、曼哈顿距离等；
    + 全文检索：比较经典，在数据存入时，通过关键词构建倒排索引；在检索时，通过关键词进行全文检索，找到对应的记录；
    #### 注入prompt
    Prompt作为大模型的直接输入，是影响模型输出准确率的关键因素之一；Prompt一般包括任务描述、背景知识（检索得到）、任务指令（一般是用户提问）等，也可以在Prompt中适当加入其他指令优化大模型的输出；

    原始RAG

    RAG 管道从一个文本文档语料库开始，直接跳过如何通过数据加载器从数据源获取步骤；

    标准的 RAG 流程简介：将文本分块，然后使用一些 Transformer Encoder 模型将这些块嵌入到向量中，将所有向量放入索引中，最后创建一个 LLM 提示，告诉模型根据搜索步骤中找到的上下文回答用户的查询； 运行时通过使用同一编码器模型对用户的查询进行向量化，然后搜索该查询向量的索引，找到 top-k 个结果，从数据库中检索相应的文本块，并将它们作为上下文输入到 LLM 提示中；

    提示工程是提升 RAG 流程性能的一种简便有效的方法；可以参考OpenAI 提供的详尽的提示工程指南，也可以使用deepseek，qwen， Anthropic 的 Claude，Mistral 的小型但功能强大的模型Mixtral，Microsoft 的Phi-2，以及如Llama2，OpenLLaMA，Falcon等众多开源模型作为 RAG 管道大脑；

    高级RAG流程

    1. 分块（Chunking）&向量化（Vectorisation）：为文档内容创建向量索引，在运行时搜索与查询向量余弦距离最近的向量索引，这样就可以找到与查询内容最接近语义的文档；块的大小的折衷是LLM有足够的上下文来推理，而不是足够具体的文本嵌入，以便更有效地搜索；关于块的大小，在LlamaIndex中，NodeParser 类很好支持解决这个问题，其中包含一些高级选项，例如定义自己的文本拆分器、元数据、节点/块关系等；向量化就是选择一个搜索优化的模型来嵌入块，查看 MTEB 排行榜以获取最新更新的模型；
    2. 搜索索引：
    3. 向量存储索引：RAG 管道的关键部分是搜索索引，它存储了在上一步中获得的向量化内容，最原始的实现是平面索引，查询向量和所有块向量之间的暴力计算距离；为了实现高效索引，搜索索引应该采用向量索引，比如 faiss、nmslib 以及 annoy，这些工具基于近似最近邻居算法，如聚类、树结构或HNSW算法；还有一些托管解决方案，如 OpenSearch、ElasticSearch 以及向量数据库，它们自动处理上面提到的数据摄取流程，例如Pinecone、Weaviate和Chroma；还可以存储元数据，使用元数据过滤器来按照日期或来源等条件进行信息检索；LlamaIndex 支持多种向量存储索引，同时也兼容其他简单的索引类型，如列表索引、树索引和关键词表索引；
    4. 分层索引：在大型数据库的情况下，可以创建两个索引，一个由摘要组成另一个由文档块组成，然后分两步进行索引；
    5. 假设性问题：让 LLM 为每个块生成一个问题，并将这些问题嵌入到向量中，在运行时对这个问题向量进行查询搜索，将块向量替换为索引中的问题向量，然后在检索后路由到原始文本块并将它们作为 LLM 获取答案的上下文发送；
    6. HyDE 的反向逻辑方法：要求 LLM 在给定查询的情况下生成一个假设的响应，然后将其向量与查询向量一起使用来提高搜索质量；
    7. 内容增强：将相关的上下文组合起来供 LLM 推理，以检索较小的块以获得更好的搜索质量，一种方法是围绕较小的检索块的句子扩展上下文，另一种是递归的将文档拆分为多个较大的父块，其中包含较小的子块；
      • 语句窗口检索器：此时文档中的每个句子都是单独嵌入的，这为上下文余弦距离搜索提供了极大的查询准确性，然后设置上下文窗口为检索到的句子前后的 K 个句子，然后将扩展的上下文发送到LLM；
      • 自动合并检索器（或父文档检索器)：文档被拆分为较小的子块，这些子块和较大的父块有引用关系；首先在检索过程中获取较小的块，然后如果前 k 个检索到的块中有超过 n 个块链接到同一个父节点（较大的块），将这个父节点替换成给 LLM 的上下文；搜索仅在子节点索引中执行；
    8. 融合检索或混合搜索：结合传统的基于关键字的搜索（稀疏检索算法，如 tf-idf 或搜索行业标准 BM25）和现代语义或向量搜索，并将其结果组合在一个检索结果中，关键是如何组合不同相似度分数的检索结果，通过 Reciprocal Rank Fusion 算法来解决，该算法有效地对检索的结果进行重新排序，已得到最终的输出结果；

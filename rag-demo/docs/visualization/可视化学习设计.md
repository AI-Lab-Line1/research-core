# RAG Demo 可视化学习设计

## 1. 可视化目标

这个 demo 的可视化不是装饰，而是为了帮助理解 RAG 每一步发生了什么。

核心目标：

- 看见文本如何被切分
- 看见不同切分方法的差异
- 看见 chunk 如何生成向量
- 看见向量如何写入索引
- 看见用户问题如何被检索
- 看见检索结果如何进入上下文
- 看见不同方法最终答案的差异

---

## 2. 建议页面布局

### 2.1 顶部导航

建议包含几个主标签页：

- 知识库
- 切分
- 索引
- 检索
- 问答
- 对比
- 日志

### 2.2 知识库页面

展示内容：

- 原始 `知识库.md`
- 文档字数
- 段落数
- 识别到的主题或标题
- 当前文档版本

学习目的：

- 让用户先知道输入数据是什么
- 理解数据质量会影响后续所有环节

### 2.3 切分页面

展示内容：

- 原文左侧展示
- chunk 列表右侧展示
- 不同颜色标注不同 chunk
- 每个 chunk 显示：
  - chunk_id
  - 字符数 / token 数
  - 所属主题
  - overlap 范围
  - 元数据

支持对比的方法：

- 固定长度切分
- 段落切分
- 标题结构切分
- 递归切分
- TF-IDF 语义凝聚度切分，可查看边界相似度、切分原因和合并单元数

学习目的：

- 理解 chunk 太大、太小、切断语义分别会带来什么问题

### 2.4 索引页面

展示内容：

- chunk 到 embedding 的映射
- embedding 维度
- 当前索引条数
- 写入状态
- 每个 chunk 的元数据

如果需要更直观，可以用降维可视化展示向量点位：

- PCA
- t-SNE
- UMAP

但是否做降维图，需要你确认，因为这会增加实现复杂度。

学习目的：

- 理解文本会被转换为向量
- 理解向量相近不等于文本完全一样
- 理解索引里不只是向量，还要存文本和元数据

### 2.5 检索页面

展示内容：

- 用户问题
- 问题向量化状态
- 检索出的 top-k chunk
- 每个 chunk 的相似度分数
- 命中的关键词，如果有 BM25
- rerank 前后顺序对比

学习目的：

- 理解召回和排序不是一回事
- 理解向量检索和关键词检索的差异
- 理解为什么 top-k 参数会影响答案

### 2.6 问答页面

展示内容：

- 用户输入框
- 最终答案
- 引用来源
- 被送入 LLM 的上下文
- prompt 预览
- 兜底提示

学习目的：

- 理解 LLM 并不是直接读取整个知识库
- 理解答案质量取决于检索到的上下文

### 2.7 对比页面

展示内容：

- 同一个问题下，不同方法的结果并排展示
- 对比项：
  - chunk 数量
  - 检索 top-k
  - 最终上下文
  - 答案
  - 引用
  - 耗时
  - 人工评分

学习目的：

- 直观看到不同方法的优缺点
- 建立“没有万能 RAG 方法”的认识

### 2.8 日志页面

展示内容：

- 每次问题的 trace
- 方法参数
- 检索结果
- prompt
- 答案
- 耗时
- 错误信息

学习目的：

- 学会调试 RAG
- 学会从检索和生成两个层面定位问题

## 3. 可视化对象设计

### 3.1 Chunk Card

每个 chunk 可以展示为一张卡片。

字段：

```text
chunk_id
section
text_preview
length
metadata
score
selected_for_context
```

### 3.2 Pipeline Step

每一步可以展示为流程节点。

字段：

```text
step_name
input
output
duration_ms
status
detail
```

### 3.3 Method Result

每种方法的结果保持统一结构。

字段：

```text
method_name
chunking_result
indexing_result
retrieval_result
context_result
answer_result
metrics
```

## 4. 不同方法的可视化重点

### 4.1 固定长度切分

重点展示：

- 切分边界是否打断语义
- overlap 如何工作
- chunk 长度是否均匀

### 4.2 标题结构切分

重点展示：

- 标题路径如何进入元数据
- chunk 是否更接近真实主题

### 4.3 向量检索

重点展示：

- 相似度分数
- 语义相似但关键词不同的命中

### 4.4 关键词检索

重点展示：

- 命中的关键词
- 精确词匹配的优势

### 4.5 混合检索

重点展示：

- 向量检索结果
- 关键词检索结果
- 合并后的排序

### 4.6 重排

重点展示：

- rerank 前顺序
- rerank 后顺序
- 哪些 chunk 被提升或降低

## 5. 需要你确认的问题

以下功能会影响复杂度，暂时不做决定：

1. 是否需要 embedding 降维散点图
2. 是否需要支持多个问题并排对比
3. 是否需要保存历史问答日志
4. 是否需要前端展示完整 prompt
5. 是否需要支持手动调整 chunk_size 和 overlap
6. 是否需要支持上传新的知识库文件

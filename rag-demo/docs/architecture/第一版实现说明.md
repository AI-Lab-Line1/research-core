# 第一版实现说明

## 主流程

第一版使用一套完全本地、轻量、可复现的实现跑通端到端流程：

1. `MarkdownLoader` 读取 `知识库.md`，统计段落和可识别章节。
2. `StructureChunker` 以空行作为主要边界，从 `标题:` 或 `标题：` 前缀提取章节元数据。
3. `jieba` 对中文文本分词并过滤常见虚词。
4. `TfidfVectorizer` 为 chunk 生成 TF-IDF 稀疏向量。
5. 内存索引保存向量、原文和元数据，并提供向量摘要给前端。
6. 用户问题使用同一个向量器转换，按余弦相似度返回 Top-K。
7. 上下文构造器按排名拼装证据块和引用编号。
8. 教学型生成器从证据中抽取高相关句子；证据覆盖不足时拒绝回答。
9. API 返回答案、引用、检索结果、上下文、Prompt 预览和每一步耗时。

## 为什么第一版用 TF-IDF

TF-IDF 不是现代 RAG 中常见的稠密语义 embedding，但它适合作为第一条学习基线：

- 不需要下载大型模型
- 每个向量维度对应可理解的词项
- 可以直观看到词权重、稀疏向量和余弦相似度
- 容易暴露关键词方法对近义表达能力不足的问题

后续接入稠密 embedding 时，前端可以沿用同一个 `IndexStatus`、`Chunk.vector` 和检索结果协议进行对比。

## 当前边界

- 索引保存在进程内存中，服务重启后自动重建。
- 当前只读取项目内的一份 Markdown 文件。
- 当前只实现结构切分和 TF-IDF 检索。
- 当前生成阶段不调用 LLM。
- 当前只支持单轮问题，不保存会话历史。

## 后续扩展顺序

建议按以下顺序逐步增加方法：

1. 固定长度 + overlap 切分，形成第一组切分对照。
2. BM25 关键词检索，形成检索算法对照。
3. 中文稠密 embedding，展示语义检索。
4. BM25 + embedding 的混合检索。
5. Cross-Encoder rerank，展示召回与排序的区别。
6. 接入用户选定的 LLM，替换教学型抽取生成器。
7. 增加问题集、命中率和人工评分，对不同方法做可重复评测。

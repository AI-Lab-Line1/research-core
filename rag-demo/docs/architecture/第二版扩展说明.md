# 第二版扩展说明

## 1. 本轮目标

第一版只用一条固定路线跑通 RAG。第二版把几个关键阶段变成可切换策略，并保持统一的输入输出结构：

```text
Markdown
  -> Chunker(structure | fixed_length)
  -> SearchIndex(tfidf | bm25 | hybrid)
  -> Retriever Top-N
  -> Reranker(none | term_coverage)
  -> Context Builder
  -> Extractive Generator
```

前端选择方法后，后端只替换对应模块，其余数据流不变。因此对比结果主要反映被替换模块的差异。

## 2. 两种切分方法

### 2.1 结构切分

结构切分以 Markdown 空行分隔的段落为边界，并从“标题：正文”形式中推断章节。

优点：

- 一个 chunk 通常表达完整主题
- 章节元数据天然可用于引用和过滤
- 小型、结构清楚的知识库效果稳定

局限：

- 高度依赖原始文档排版
- 不同 chunk 长度可能差异很大
- 超长段落仍需要句子级二次切分

### 2.2 固定长度切分

固定长度切分使用滑动窗口：

```text
下一窗口起点 = 当前窗口起点 + chunk_size - chunk_overlap
```

例如 `chunk_size=180`、`chunk_overlap=30` 时，每次向前移动 150 个字符。重复区域能降低关键信息刚好落在边界两侧的风险，但也可能造成重复召回和重复回答。

## 3. 三种检索方法

### 3.1 TF-IDF

TF-IDF 同时考虑词在当前 chunk 中出现的频率，以及该词在整个知识库中的稀有程度。项目将 chunk 和问题都转换为稀疏向量，然后计算余弦相似度：

```text
cosine(q, d) = (q · d) / (||q|| * ||d||)
```

它适合解释“哪些词贡献了相似度”，但不能真正理解没有共同词的近义表达。例如“借书规则”和知识库中的“可借 20 本书”可能因分词后缺少共同词而无法匹配，这不是调高 Top-K 就一定能解决的问题。

### 3.2 BM25

BM25 是经典关键词排序方法。它在 TF-IDF 思路上进一步处理：

- 词在文档中重复很多次后，收益逐渐饱和
- 长文档不会仅因包含更多词而天然占优
- 稀有查询词比常见词贡献更高

当前实现使用 `rank-bm25`，分词仍由 `jieba` 完成。

### 3.3 混合检索

当前混合方法不是稠密语义检索，而是 TF-IDF 与 BM25 的教学型融合。先分别检索，再按各自最大值归一化：

```text
fused = 0.55 * normalized_tfidf + 0.45 * normalized_bm25
```

前端会同时展示两个分量。这样可以直接观察某个 chunk 是两种方法都认可，还是主要由其中一种方法推高。

## 4. 两阶段检索与重排

不重排时，检索器直接返回 Top-K。

启用查询词覆盖率重排时，流程变为：

1. 初次检索扩大到 `3 * Top-K` 个候选。
2. 计算每个候选覆盖了多少查询词。
3. 融合原始检索分数与覆盖率。
4. 重新排序并截取最终 Top-K。

```text
rerank = 0.65 * normalized_retrieval + 0.35 * term_coverage
```

这是为了讲清楚“召回”和“精排”是两个阶段。它不具备 Cross-Encoder 的语义判断能力。

## 5. 方法对比的公平性

对比页采用控制变量方式：

- 检索对比：切分、重排、Top-K 相同，只改变检索方法
- 切分对比：检索、重排、Top-K 相同，只改变切分方法

每套配置使用独立 `RagPipeline`，避免前一套配置重建的索引污染后一套结果。对比项包括 chunk 数量、命中数量、上下文数量、耗时、答案和前三条证据。

## 6. 当前没有实现的能力

- Embedding 深层语义切分：后续版本已先补充 TF-IDF 语义凝聚度基线，Sentence Embedding 版本仍需选择模型和阈值方案
- 稠密向量检索：需要选择中文 Embedding 模型与本地/远程运行方式
- Cross-Encoder 重排：需要额外模型推理
- LLM 生成：需要选择本地模型或 API 供应商
- 向量数据库：当前小知识库使用内存索引更便于观察原理

这些模块的接口仍保留，但接入前需要先确定模型、机器资源和是否允许外部 API。

# RAG Demo 总体架构

## 1. 项目最终构想

本项目最终希望实现一个浏览器可访问的 RAG 学习型 Demo。

用户打开前端页面后，可以：

1. 查看当前小型知识库
2. 选择不同 RAG 方法
3. 观察不同方法如何切分文本
4. 观察 chunk 如何生成向量
5. 观察向量如何写入索引
6. 输入问题进行问答
7. 查看检索命中的片段
8. 查看最终上下文如何拼装
9. 查看模型如何基于上下文生成答案
10. 对比不同方法的效果、速度和优缺点

这个项目不只是一个“能问答”的工具，而是一个“能解释 RAG 全流程”的教学型系统。

---

## 2. 总体分层

建议整体分成 5 层。

```text
Browser Frontend
  -> API Backend
    -> RAG Pipeline Orchestrator
      -> Data Processing / Indexing / Retrieval / Generation
        -> Storage Layer
```

### 2.1 前端层

前端负责展示和交互。

核心职责：

- 展示知识库原文
- 展示切分结果
- 展示索引状态
- 展示问答界面
- 展示检索结果
- 展示上下文构造过程
- 展示不同方法对比

### 2.2 后端 API 层

后端负责向前端提供统一接口。

核心职责：

- 读取知识库
- 触发切分
- 触发向量化
- 触发索引写入
- 接收用户问题
- 返回检索过程和答案
- 返回可视化所需的中间数据

### 2.3 RAG Pipeline 编排层

编排层负责串起完整流程。

核心职责：

- 根据前端选择的方法，调用对应 pipeline
- 统一记录每一步中间结果
- 保证不同方法输出结构一致，方便前端对比

### 2.4 RAG 方法层

这里放不同 RAG 实现方法。

初步预留这些路线：

- 基础向量检索 RAG
- 标题/段落结构切分 RAG
- 关键词检索 RAG
- 混合检索 RAG
- 带重排 RAG
- 带上下文压缩 RAG

是否全部实现，需要你确认优先级。

### 2.5 存储层

存储层负责保存数据和索引。

可能包含：

- 原始文档
- chunk 数据
- embedding 数据
- 向量索引
- 关键词索引
- 问答日志
- 评测结果

## 3. 核心流程

### 3.1 离线处理流程

```text
加载 知识库.md
-> 解析 Markdown / 普通文本
-> 按所选方法切分 chunk
-> 为每个 chunk 生成元数据
-> 为每个 chunk 生成 embedding
-> 写入向量索引
-> 保存切分和索引状态
```

### 3.2 在线问答流程

```text
用户输入问题
-> 选择 RAG 方法
-> 查询预处理
-> 检索候选 chunk
-> 可选重排
-> 构造上下文
-> 调用大模型生成答案
-> 返回答案、引用和中间过程
```

---

## 4. 多方法对比思路

为了学习 RAG，全项目应该避免只保留一种固定方法。

建议把每种方法都抽象成同样的输入输出：

```text
输入：知识库文本 + 用户问题 + 方法参数
输出：切分结果 + 检索结果 + 上下文 + 答案 + 日志
```

这样前端就可以横向对比：

- 方法 A 切了多少 chunk
- 方法 B 的 chunk 是否更完整
- 方法 C 检索到了哪些内容
- 哪种方法最终回答更准确
- 哪种方法更慢
- 哪种方法更容易产生无关召回

---

## 5. 需要保留的中间结果

为了可视化学习，后端不能只返回最终答案，需要返回完整 trace。

建议每次问答保留：

- 原始问题
- 改写后的问题，如果有
- 使用的方法名称
- 检索参数
- 候选 chunk 列表
- 每个 chunk 的分数
- rerank 后顺序，如果有
- 最终选入上下文的 chunk
- prompt 预览
- 最终答案
- 引用来源
- 耗时统计

---

## 6. 前后端交互初步模块

前端页面可以先规划为 6 个区域：

1. **知识库区**
   - 展示原始 `知识库.md`

2. **方法选择区**
   - 选择不同切分、检索、重排方案

3. **索引构建区**
   - 展示当前方法下的 chunk 和 embedding 状态

4. **问答区**
   - 用户输入问题并查看答案

5. **检索可视化区**
   - 展示命中 chunk、分数和排序

6. **流程追踪区**
   - 展示从问题到答案的完整步骤

## 7. 暂不做的事情

- 前端框架
- 后端框架
- embedding 模型
- LLM 提供商
- 向量数据库
- 是否使用 LangChain / LlamaIndex
- 是否需要数据库

这些都放到待确认问题里，由你确认后再进入实现阶段。
